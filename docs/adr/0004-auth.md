# ADR-0004: Authentifizierung

- **Status:** Accepted
- **Datum:** 2026-10-02
- **Roadmap:** 0.2, 1.6

## Kontext

Gemeint ist die Anmeldung an der Instanz, nicht an den Mailkonten, dazu Geräteverwaltung und Session-Rotation. SSO ist bewusst nicht im MVP.

## Optionen

1. **Serverseitige Sessions mit HttpOnly-Cookie**: einfach widerrufbar, passt zu einer PWA auf derselben Origin.
2. **JWT Access + Refresh Tokens**: nützlich für native Clients, aber der Widerruf ist aufwendiger.
3. **Zusätzliche Faktoren**: TOTP, Passkeys.

## Entscheidung

- **Single-User-Instanz:** Es gibt genau ein Benutzerkonto und keine Registrierung. Der Benutzer wird beim ersten Start über ein Setup-Formular angelegt (oder per Env-Variablen). Das Datenmodell bleibt mehrbenutzerfähig (`user_id` überall), damit später Einladungen möglich sind.
- **Nur Passwort** (Argon2id) im MVP. TOTP und Passkeys kommen später.
- **Serverseitige Sessions** mit `HttpOnly`-/`Secure`-/`SameSite`-Cookie für PWA und Browser. Native Clients (ADR-0010) bekommen später ein gerätegebundenes Token in derselben Session-/Geräte-Tabelle.

## Konsequenzen

- CSRF-Schutz ist erforderlich (6.4).
- Weil es nur ein Passwort gibt, sind **Rate Limits und Lockout am Login** Pflicht, und zwar schon in Phase 1, nicht erst in Phase 6.
- Die Geräte-Tabelle ist die gemeinsame Basis für Sessions und Push-Subscriptions.
