# ADR-0005: Push-Zustellung

- **Status:** Accepted
- **Datum:** 2026-10-02
- **Roadmap:** 0.2, 4.3, 8.1

## Kontext

Benachrichtigung über neue Mails auf der iOS-PWA (Priorität), im Browser und später auf nativen Clients, ohne Mailinhalte preiszugeben. Details: [`../architecture/push.md`](../architecture/push.md).

## Optionen

1. **Direkter Web Push (VAPID) aus der Instanz**: Außer dem Push-Dienst des Browsers ist keine Drittpartei beteiligt.
2. **Über ein Hosted Push Relay**: nötig für APNs und eine native App, Komfort für nicht öffentlich erreichbare Instanzen.

## Entscheidung

**Direkter Web Push als Default und Pflichtfunktion.** Ein Relay ist optional und kommt frühestens in Phase 8 bzw. mit nativen Clients. Der Payload enthält nur Ereignistyp, Installations-ID und Badge.

## Konsequenzen

- Das Subscription-Modell hat ein Feld `transport` (`webpush`, `apns`, `relay`).
- Der VAPID-Private-Key wird wie ein Secret behandelt (Env, siehe ADR-0007).
- iOS-Web-Push braucht eine öffentlich erreichbare HTTPS-Instanz mit gültigem Zertifikat. Das deckt Caddy aus ADR-0007 ab.
